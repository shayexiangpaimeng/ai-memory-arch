# 世界书条目化：为什么记忆库用 JSON 条目，不用一篇长文

## 问题

把设定和事实写成一整篇长文塞进上下文，有两个致命伤：

1. 上下文放不下 → 每次对话都要全量加载，token 爆炸
2. 全量加载了也记不住 → 长文的关键事实淹没在叙述里

## 解法：条目化 + 触发词 + 检索

```
记忆库（JSON）
├── uid 2   用户画像        → 触发词: [用户, 雷铭]
├── uid 4   当前状态        → 常驻，每轮注入
├── uid 5   关系里程碑      → 常驻，每轮注入
└── uid 19  某设定条目      → 触发词: [关键词A, 关键词B]
```

- **常驻条目**（当前状态、关系里程碑）：每轮注入上下文，是「不能忘」的部分
- **按需条目**（设定细节、旧摘要）：靠触发词召回，平时不占上下文
- **检索方式**：BM25 + n-gram 混合召回（纯本地，无云端依赖）

## 收益

- 上下文只装常驻条目的 2 条，其余按需加载
- 新增事实 = 新条目，不污染旧条目
- 触发词即索引，召回比翻长文快一个量级

## 踩坑记录

- 曾把所有设定塞进 1 个条目 → 召回失焦，命中率暴跌
- 关键亲属关系（比如家谱）没建条目 → 模型「认不出人」，这是数据缺失不是模型笨
- 旧摘要只增不清理 → 建立归档层，过期条目移入 _archive
