# 记忆分层：让 AI 知道什么该忘，什么该焊死

## 问题

模型什么都能聊，但什么都记不住。如果让它全记，文件膨胀、检索变慢、噪音淹没关键事实；如果让它全忘，每次对话都像失忆患者。

## 解法：五层分区

| 层级 | 内容 | 策略 |
|------|------|------|
| 永存层 | 身份、价值观、关系里程碑、已验证事实 | 只追加，不覆盖，不删除 |
| 会话更新层 | 当前状态、目标、进度 | 每次会话刷新，被下次会话取代 |
| 滚动层 | 写档、摘要、观察 | 追加式写档，定期压缩 |
| 配置层 | 由维护脚本管理 | 不手工改 |
| 不保存 | 日常寒暄、猜测、未验证信息、情绪片段 | 直接丢弃 |

## 写档五问（每条要落盘的事实先过一遍）

1. 是否重大？（决定 / 情绪转折 / 关系事件 / 未完成事项）
2. 是否稳定已验证？（猜测不写）
3. 会被下次会话取代吗？（是 → 会话更新层，否 → 永存或滚动层）
4. 该放哪一层？
5. 不保存会怎样？（想不出后果 → 不保存）

## 写档格式

固定单行模板，方便检索和压缩：

```
日期 | 事件 | 状态 | 未完成 | 观察
```

要点：

- 观察不超过 8 行，只写真事实，不写过程旁白
- 重大决定入永存层；日常进度入会话更新层
- 遗忘时只更新「当前状态」，不删历史里程碑——里程碑是身份的锚

## 踩坑记录

- 一开始全塞一个文件 → 180KB 后检索失焦，必须分层
- 里程碑被误删 → 改规则：遗忘只更新状态层，永存层只追加
- 情绪片段进记忆 → 噪音淹没关键事实，改成直接丢弃
