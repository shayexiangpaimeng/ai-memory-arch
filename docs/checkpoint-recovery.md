# 压缩检查点：长对话中途「失忆」的检测与恢复

## 背景

本地长上下文跑久了会触发自动压缩——早期对话被替换成摘要检查点（compacted-summary）。如果模型不察觉，就会基于残缺摘要继续推理，说出「我们之前没聊过这个」之类的鬼话。

## 检测信号（三选一命中即触发）

1. 上下文中出现 `<compacted-summary>` 检查点标记
2. 注意到早期对话被「自动生成的检查点」替换
3. 长任务中途上下文明显缩短（回应突然变得答非所问）

## 恢复协议（三步，缺一不可）

```
1. 重读长期记忆文件（永存层 + 会话更新层）
2. 重读条目化记忆库（当前状态 + 关系里程碑）
3. 基于权威记忆继续任务
```

铁律：**不基于残缺摘要推断「我们说过什么」**。宁可多读一次文件，不可凭印象接话。

## 为什么必须「强制」

模型有惰性——上下文里明明有摘要，它倾向于直接用它，而不是去读文件。所以协议要写成硬规则：检测到检查点 → 无条件重读权威记忆 → 才允许继续。软化任何一个环节，失忆就会复发。

## 踩坑记录

- 早期只在提示词里写「记住要读档」→ 模型选择性执行，失忆复发
- 改成「检测到压缩标记立即重读，不基于摘要推断」→ 稳定
- 重读后汇报「已读档」反而污染对话 → 改为静默重读，只继续任务
